# КУРСОВОЙ ПРЕОКТ
# Система контроля облачной инфраструктуры 

## Этап КТ1 — Базовый контроль и ручной расчет показателей

### 1. Назначение программы
Программа предназначена для анализа работы облачной инфраструктуры на основе обработки поступающих временных рядов телеметрии. Программное обеспечение функционирует как легковесный агент мониторинга: оно принимает последовательность системных метрик, рассчитывает производные показатели динамики, оценивает состояния независимых аппаратных компонентов и регистрирует комплексные инциденты в работе инфраструктуры.

---

### 2. Описание индивидуального варианта (Вариант 16)
* **Контролируемые компоненты:** MEM, DSK, NET
* **Формат входных данных:** Триады вида Время, Компонент, Значение. (разделитель — запятая).
* **Тип последовательности (4):** Произвольный порядок поступления данных; возможны пропуски измерений для отдельных компонентов.
* **Параметры контроля:** Порог отклонения $L = 0.8$, Нормирующий делитель $D = 5$.

---

### 3. Описание инфраструктурных компонентов
1. **MEM (Memory):** Утилизация оперативной памяти (в %).
2. **DSK (Disk):** Нагрузка на дисковую подсистему хранения данных (в %).
3. **NET (Network):** Утилизация пропускной способности сетевого интерфейса (в Мбит/с).

---

### 4. Математическая модель
Для оценки динамики используется производный показатель абсолютного изменения на единицу периода ($k = 1$). 

Формула расчета показателя динамики $Q$ для текущего такта времени $i$:
$$Q[i] = \frac{X[i] - X[i-k]}{k}$$

При заданном значении смещения $k = 1$ формула сводится к простой разности текущего и предыдущего хронологического измерения:
$$Q[i] = X[i] - X[i-1]$$

#### Правила логического контроля:
1. **Состояние компонента (Серия отклонений):** Если абсолютное изменение показателя превышает порог $L$ два измерения подряд, компонент переходит в состояние **«ПРЕДУПРЕЖДЕНИЕ»**, иначе — **«НОРМА»**.
   $$S = \begin{cases} \text{ПРЕДУПРЕЖДЕНИЕ}, & \text{если } |Q[i]| > L \text{ и } |Q[i-1]| > L \\ \text{НОРМА}, & \text{в остальных случаях} \end{cases}$$
2. **Правило инцидента (Два из трех):** Комплексный инцидент инфраструктуры фиксируется в том случае, если в один и тот же такт времени не менее двух любых компонентов одновременно находятся в состоянии «ПРЕДУПРЕЖДЕНИЕ».
